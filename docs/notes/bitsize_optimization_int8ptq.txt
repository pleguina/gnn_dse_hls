BITWIDTH OPTIMIZATION WORKFLOW FOR INT8 GRAPHSAGE HLS

This document describes the methodology to fully optimize bit-widths for the pure-INT8 GraphSAGE HLS implementation, starting from the Python/PTQ model, and automatically generating safe and minimal bit-widths for:

Adjacency (adj_t)

Accumulators (acc_t)

Bias (bias_t)

Fixed-point scales (scale_fp_t)

Scaling products (mult_t)

The goal is to avoid oversized types (int32/int64) while maintaining numerical safety and correctness.

WHY BIT-WIDTH OPTIMIZATION IS NECESSARY

Initial safe design uses:

INT8 activations and weights

INT16 adjacency

INT32 accumulators

INT64 scaling products

This guarantees correctness but:

Wastes DSPs

Wastes LUTs

Increases power

Reduces packing efficiency

To optimize, we must:

Find true numerical bounds of intermediate values.

Choose minimum safe number of bits.

Generate HLS ap_int<N> types automatically from Python.

KEY NUMERICAL QUANTITIES TO BOUND

The entire kernel only has a few critical large values:

Integer adjacency:
A_int[i,j] = round(A_float[i,j] * 2^K_BITS)

Aggregation sum:
tmp[i,f] = sum_j (A_int[i,j] * q_in[j,f])

Linear accumulator:
acc[n,o] = bias_int[o] + sum_f (q_in[n,f] * w_int8[o,f])

Scaled values:
scaled = tmp * beta_fp
scaled = acc * eff_scale_fp

Bias:
bias_int[o]

These define all required bit-widths.

WHAT MUST BE EXTRACTED FROM PYTHON

From the graph / dataset:

deg_max = maximum node degree in subgraphs

A_float_max = maximum absolute adjacency value

After scaling:
A_int_max = max |round(A_float * 2^K_BITS)|

From the quantized model (PTQ exports):

For each linear layer:

F_in = input feature dimension

weight_int8_max = max |weight| (usually 127)

bias_int32_max = max |bias after quantization|

From the fixed-point scales:

beta_fp

eff_scale_fp

record max absolute values if desired

Optional but recommended (data-driven):

max_abs_tmp_agg_layer1

max_abs_acc_lin_layer1

max_abs_tmp_agg_layer2

max_abs_acc_lin_layer2

max_abs_output

These can be obtained by running a pure integer simulation in Python that mirrors the HLS equations.

THEORETICAL BIT-WIDTH FORMULAS (FAST METHOD)

Let:

feat_max = 127 (INT8)

w_max = 127 (INT8)

deg_max = maximum node degree

A_int_max = max integer adjacency value

F_in = feature size entering a linear layer

bias_int_max = max absolute quantized bias

AGGREGATION ACCUMULATOR:

|tmp| ≤ deg_max * A_int_max * feat_max

Required bits:

ACC_BITS_agg > log2(deg_max) + log2(A_int_max) + log2(feat_max) + 1

LINEAR ACCUMULATOR:

|acc| ≤ max( |bias_int_max| , F_in * feat_max * w_max )

Required bits:

ACC_BITS_lin > max(
log2(|bias_int_max|),
log2(F_in) + log2(feat_max) + log2(w_max)
) + 1

FINAL ACCUMULATOR BIT-WIDTH:

ACC_BITS = max(ACC_BITS_agg, ACC_BITS_lin) + safety_margin

ADJACENCY BIT-WIDTH:

If A_int = round(A_float * 2^K_BITS):

A_int_max ≤ 2^K_BITS

So:

ADJ_BITS ≥ K_BITS + 1 + safety_margin

SCALE BIT-WIDTH:

Fixed-point scales store M fractional bits:

SCALE_BITS ≥ M_BITS + safety_margin (typically +6 to +8)

SCALING PRODUCT BIT-WIDTH:

mult = acc * scale_fp

Required:

MULT_BITS ≥ ACC_BITS + SCALE_BITS

DATA-DRIVEN BIT-WIDTH EXTRACTION (TIGHT METHOD)

Instead of theoretical worst-case bounds, you can simulate integer arithmetic in Python:

For each sample graph:

Generate A_int using K_BITS.

Use real quantized INT8 inputs and weights.

Compute tmp, acc, and scaled exactly as in HLS.

Track:

max_abs_tmp_agg

max_abs_acc_lin

max_abs_scaled

max_abs_bias

max_abs_output

Then compute:

BITS_tmp = ceil(log2(max_abs_tmp_agg)) + 1 + margin
BITS_acc = ceil(log2(max_abs_acc_lin)) + 1 + margin
BITS_bias = ceil(log2(max_abs_bias)) + 1 + margin
BITS_scaled= ceil(log2(max_abs_scaled)) + 1 + margin

Then choose:

ADJ_BITS = ceil(log2(A_int_max)) + 1 + margin
ACC_BITS = max(BITS_tmp, BITS_acc, BITS_bias)
MULT_BITS = BITS_scaled

This gives true minimal safe widths for your trained model.

AUTO-GENERATED HLS CONFIG HEADER

From Python, generate:

auto_generated_bitwidths.h

Example:

#define K_BITS 12
#define ADJ_BITS 15
#define ACC_BITS 27
#define SCALE_BITS 32
#define MULT_BITS 44

Then in HLS:

typedef ap_int<ADJ_BITS> adj_t;
typedef ap_int<ACC_BITS> acc_t;
typedef ap_int<ACC_BITS> bias_t;
typedef ap_int<SCALE_BITS> scale_fp_t;
typedef ap_int<MULT_BITS> mult_t;

This removes all manual tuning and guarantees consistency with the PTQ model.
