# HLS Implementation Guide

This directory contains the Vivado HLS implementation of the GraphSAGE network for FPGA deployment.

## Files

- `graphsage_layer.h` - Header file with type definitions and function declarations
- `graphsage_layer.cpp` - HLS C++ implementation of GraphSAGE layers
- `testbench.cpp` - Testbench for validation
- `run_hls.tcl` - TCL script for automated HLS workflow
- `Makefile` - Build automation
- `weights.h` - Quantized weights (generated by quantization step)

## Quick Start

### Option 1: C++ Testbench (No Vivado Required)

```bash
make clean
make test
```

This compiles and runs a standard C++ testbench to validate the implementation.

### Option 2: Vivado HLS Workflow

Requires Vivado HLS 2019.1 or newer.

#### Run All Steps
```bash
vivado_hls -f run_hls.tcl
```

This will:
1. Create HLS project
2. Run C simulation (csim)
3. Run synthesis (csynth)
4. Run C/RTL cosimulation (cosim)
5. Export RTL as IP

#### Run Individual Steps

**C Simulation Only:**
```bash
make hls-csim
# or
vivado_hls -f run_hls.tcl -tclargs csim
```

**Synthesis Only:**
```bash
make hls-synth
# or
vivado_hls -f run_hls.tcl -tclargs synth
```

**Cosimulation Only:**
```bash
make hls-cosim
# or
vivado_hls -f run_hls.tcl -tclargs cosim
```

**Export RTL:**
```bash
vivado_hls -f run_hls.tcl -tclargs export
```

## Configuration

### Target Device

The default target is **Xilinx Zynq-7000 (xc7z020clg484-1)**.

To change the target device, edit `run_hls.tcl`:

```tcl
# Line 35
set target_device "xc7z020clg484-1"
```

Common alternatives:
- `xc7z020clg484-1` - Zynq-7000 SoC (smaller, Pynq-Z2, Zybo Z7)
- `xc7z045ffg900-2` - Zynq-7000 SoC (larger, ZC706)
- `xczu9eg-ffvb1156-2-e` - Zynq UltraScale+ MPSoC (ZCU102)

### Clock Period

Default clock period is **10ns (100MHz)**.

To change, edit `run_hls.tcl`:

```tcl
# Line 38
set clock_period 10
```

### Optimization Directives

HLS optimization pragmas are configured in `run_hls.tcl` (lines 100-125):

- **Array Partitioning**: Enables parallel access to arrays
- **Pipelining**: Improves throughput by overlapping operations
- **Interface Types**: Uses BRAM for efficient memory access

Adjust these based on your resource/performance requirements.

## Output Files

After running HLS, the following directories are created:

```
graphsage_hls/
├── solution1/
│   ├── syn/
│   │   └── report/          # Synthesis reports (timing, resources)
│   ├── sim/
│   │   └── report/          # Cosimulation reports
│   └── impl/
│       └── ip/              # Exported IP (if export was run)
```

### Key Reports

**Synthesis Report (`syn/report/csynth.rpt`):**
- Latency and throughput estimates
- Resource utilization (LUTs, FFs, BRAM, DSP)
- Interface summary

**Timing Report (`syn/report/csynth_design_timing_summary.rpt`):**
- Clock period analysis
- Critical path information

**Cosimulation Report (`sim/report/cosim.rpt`):**
- RTL vs C verification results
- Latency measurements

## Troubleshooting

### Issue: "ap_int.h not found"
**Solution**: This header requires Vivado HLS. For C++ testbench only, use `make test` instead.

### Issue: Cosimulation fails
**Solution**:
1. Verify C simulation passes first (`make hls-csim`)
2. Check that test vectors are present in `../tests/test_vectors/`
3. Review `graphsage_hls/solution1/sim/report/cosim.rpt`

### Issue: Resource utilization too high
**Solution**:
1. Reduce parallelism in `run_hls.tcl` (decrease array partition factor)
2. Remove or reduce loop unrolling
3. Use smaller model dimensions (edit `graphsage_layer.h`)

### Issue: Timing not met
**Solution**:
1. Increase clock period in `run_hls.tcl`
2. Add more pipeline stages
3. Reduce combinational logic depth

## Performance Tuning

### To Optimize for Latency

In `run_hls.tcl`, add aggressive loop unrolling:

```tcl
set_directive_unroll -factor 4 "matmul_int8/loop_k"
set_directive_unroll -factor 4 "aggregate/loop_n"
```

### To Optimize for Throughput

Increase pipeline depth:

```tcl
set_directive_pipeline -II 1 "graphsage_layer"
```

### To Reduce Resources

Use block-level pipelining instead of loop-level:

```tcl
# Remove aggressive array partitioning
# Use cyclic factor 2 instead of 4
```

## Integration with Vivado

After exporting IP:

1. Open your Vivado project
2. Add IP repository: `Settings → IP → Repository`
3. Add path: `graphsage_hls/solution1/impl/ip`
4. Instantiate the IP in your block design
5. Connect AXI interfaces and clocks
